# 02 — 코퍼스 최신화 (구 DB → 신 DB)

> 발표에서 **결과가 가장 분명한 부분**입니다. 뒤의 검색 교체(survey-search)가 음성 결과인 것과
> 대비됩니다. "무엇이 확실히 좋아졌나"를 물으면 이 장으로 답하면 됩니다.

## 1. 문제 — 배포 DB 가 2년 전에서 멈춰 있었습니다

원논문이 배포한 논문 DB 는 **2024-09-25** 에서 끝납니다. 두 가지가 따라옵니다.

1. 최신 논문을 **인용할 수 없습니다.** 서베이가 "최근 동향"을 쓸 수 없습니다.
2. 논문이 내세우는 **TRE**(2년 단위 시간창으로 최신·정착 문헌을 안배하는 리랭커)가
   **최신 창이 2년째 비어 있어 사실상 죽어 있습니다.**

즉 코퍼스를 안 고치면 파이프라인의 핵심 부품 하나가 작동하지 않는 상태였습니다.

## 2. 무엇이 어려웠나 — "그냥 더 넣으면" 되지 않습니다

증분의 전제는 **신규 논문이 기존과 구별되지 않는 형태로** 들어가는 것입니다.
그런데 배포 DB 를 열어 보니 **이미 두 층**이었고, 제목의 문자 치환 여부로 정확히 갈립니다
(교집합 0):

| 층 | 편수 | 날짜 범위 |
|---|---:|---|
| `:` → 공백 치환됨 | 149,036 | 2012-01-01 ~ **2024-04-26** |
| `:` 보존 (raw) | 21,791 | 2024-04-23 ~ 2024-09-25 |

경계 2024-04-26 은 AutoSurvey 배포 DB 의 컷오프와 같습니다. 즉 이 코퍼스는 **AutoSurvey 계열
베이스 위에 저자들이 직접 증분한 것**이고, 그 증분에서는 치환을 걸지 않았습니다.

→ 신규 논문은 **최신 층(raw 표기)** 을 따라야 합니다. 이걸 모르고 AutoSurvey 스크립트를
그대로 옮겼으면 신규 319,696편의 제목이 전부 다른 규약으로 들어갔을 것입니다.

**규약은 추측하지 않고 실측으로 확정했습니다** — 최신 층 25편을 arXiv OAI 에서 재취득해
문자 단위로 대조, **7필드 0불일치**.

| 필드 | 확정된 규약 | AutoSurvey 방식과 다른 점 |
|---|---|---|
| `date` | **id 에 적힌 버전의 날짜** | 그쪽은 v1 → 개정본이 최대 1년 어긋남 |
| `title` | arXiv 형식, **치환 없음** | 그쪽은 `<>:"/\|?*#` 를 공백 치환 |
| `abs` | arXivRaw (TeX escape 보존) | 동일 |

임베딩 규약도 저장 벡터를 복원해 맞췄습니다 — `encode(title+abs)` **구분자 없는 연결**,
L2 정규화, prefix 없음(cos 1.000000). **구분자를 하나만 끼워도 0.990 으로 떨어집니다.**

## 3. 실행 결과

```
수집 370,292건 → 기존 중복 50,511건 제외 → 제목+저자 재게시 85건 제외
              → 신규 319,696편 → 총 908,819편
```

| 단계 | 소요 | 결과 |
|---|---|---|
| 1. arXiv 수집 | 1시간 13분 | 두 패스 각 370,292건, **조인 손실 0** |
| 2. 피인용수 수집 | 15분 | 319,781편 **전수 조회 성공**, 59.2%가 >0 |
| 3. 임베딩 + append | 1시간 40분 | 67편/s (L40S 1장) |
| 4. 검증 | 3분 | **재임베딩 최저 cos 1.000000** |

| | 구 DB (배포본) | 신 DB (최신화본) |
|---|---:|---:|
| 논문 수 | 589,123 | **908,819** |
| 수록 범위 | 2012-01-01 ~ 2024-09-25 | 1991-03-13 ~ **2026-08-04** |
| 크기 | 5.5GB | 9.0GB |

배포본 589,123편은 **전부 포함**되어 있습니다. 기존 `database/` 는 읽기만 하고 최신화본을
옆에 새로 썼기 때문에 **파일럿과의 A/B 대조가 유지됩니다.**

### 검증을 이렇게 설계한 이유

건수 일치·id 전단사(1..908819)에 더해 **저장 벡터를 꺼내 다시 임베딩해 대조**했고,
표본을 **기존 구간과 신규 구간에서 반씩** 뽑았습니다.

> 기존만 보면 append 코드가 틀려도 통과하고, 신규만 보면 규약을 잘못 읽었을 때
> 나란히 틀려서 통과합니다. 한쪽만 보면 검증이 아니게 됩니다.

## 4. DB 에 넣은 것과 검색되는 것은 다릅니다

넣었다고 쓰이는 게 아니라서 따로 확인했습니다. 같은 토픽의 아웃라인 검색 풀 1,500편:

| | 구 DB | 신 DB |
|---|---|---|
| 날짜 범위 | 2015-02 ~ 2024-09-25 | 2018-08 ~ **2026-08-03** |
| 2024-09-25 이후 | **0편 (0%)** | **980편 (65.5%)** |

## 5. 회귀 검사 — 희석은 일어나지 않았습니다

최신 논문이 대거 들어오면 "옛날 정전 문헌을 안 쓰게 되는 것 아닌가"가 당연한 우려입니다.
같은 모델로 **DB 만** 바꿔 세 토픽을 생성하고 인간 서베이를 기준선으로 함께 놓았습니다.

| 토픽 | | 판정 가능 인용 안에서의 정확도 | 최신 인용 |
|---|---|---:|---:|
| **RAG** | 인간 | 54.2% | 0% |
| | 구 DB → 신 DB | 30.4% → **64.3%** | 0% → 78.1% |
| **Multi-Agent** | 인간 | 76.2% | 0% |
| | 구 DB → 신 DB | 29.5% → **61.1%** | 0% → 89.4% |
| **3DGS** | 인간 | 62.4% | 0% |
| | 구 DB → 신 DB | 60.7% → **93.8%** | 0% → 78.9% |

**세 토픽 모두 +31~34 포인트로 균일하게 오릅니다.** 편차가 2.3p 뿐이고 출발점과 무관합니다
(3DGS 는 구 DB 가 이미 60.7% 였는데도 같은 폭). 그래서 "못하던 게 고쳐졌다"가 아니라
**"배분이 바뀌었다"** 로 읽어야 합니다 — 인용 슬롯의 약 80%가 최신 논문으로 가고,
남은 20%를 훨씬 정확하게 고릅니다.

### 주장할 때 지켜야 할 선

- **"인간을 넘었다"고 쓰지 마세요.** 3개 중 2개만 넘었습니다(Multi-Agent 는 61.1 vs 76.2).
- **이 정확도는 분모가 실행마다 다릅니다.** 최신 논문을 많이 인용할수록 분모가 작아집니다
  (RAG 는 125 → 28). 그래서 이 표는 **인간 기준선과 나란히 놓아야만** 읽힙니다.
  분모 문제 자체는 [03-evaluation.md](03-evaluation.md) 에서 정면으로 다룹니다.

## 6. 남은 제약

- **서베이 DB·아웃라인 코퍼스는 여전히 2024-09** 입니다. 최신 논문을 인용하지만
  **최신 서베이의 구조는 학습하지 않습니다.**
- 배포본 서베이 DB 자체에 결함이 있습니다 — 레코드 18,816개인데 벡터가 12,756개뿐이라
  6,060편은 검색되지 않습니다.
- 컷오프 게이트가 하드코딩돼 있어 DB 를 갱신해도 신규 논문을 조용히 가렸습니다.
  파라미터화하고 **폐기 건수를 매 실행 보고**하도록 고쳤습니다.
