# 05 — 한계와 다음 단계

## 1. 이 결과로 말할 수 있는 것 / 없는 것

| | |
|---|---|
| **말할 수 있다** | 어댑터가 실호스트에서 끝까지 돈다 (2토픽 완주, 오염 0) |
| | 검색 레이어 자체는 개선됐다 (SurGE R@1500 38.7% → 57.5%) |
| | 3DGS 에서 정전 문헌 적중이 떨어졌다 (p<0.0001) |
| | 손실 지점은 검색이 아니라 서브섹션 랭킹이다 (풀은 같고 전환율이 다름) |
| **말할 수 없다** | 서베이 전체 품질이 나빠졌는지 — 인용 축만 쟀다 |
| | 컷오프 이후 인용(전체의 75%)이 좋은지 나쁜지 |
| | RAG 토픽에서의 차이 (p=0.064, 경계선) |
| | 토픽 일반화 — **토픽 2개, 실행 1회씩** |

## 2. 알려진 한계

**① 표본이 작습니다.** 토픽 2개 × 실행 1회. `temperature=1` 에 시드가 없어 실행 간
분산을 모릅니다. 최소 3회 반복이 필요합니다.

**② 벤치마크가 산출물의 75%를 못 봅니다.** 정답이 과거 시점 서베이의 인용 목록이라
구조적입니다. 지표를 바꿔서 풀리지 않습니다 ([02-evaluation.md](02-evaluation.md) §2).

**③ 품질 축이 인용 하나뿐입니다.** 서술의 정확성·구성·가독성은 안 쟀습니다.
SurveyBench 의 LLM judge 축(SAM-O/SAM-C)은 별도 비용이 듭니다.

**④ 인용 정합성 자체가 미검증입니다.** 인용 번호는 LLM 이 쓴 제목을 임베딩 최근접
(top_k=1)으로 스냅한 것이라 임계값이 없습니다. **본문이 실제로 그 논문을 근거로 하는지는
확인하지 않았습니다.** 이건 원본 SurveyForge 부터의 구조적 문제입니다.

**⑤ 첫 실행 1편에 오염이 있습니다.** RAG arm 은 facet 분해 실패 2건(규칙 기반 fallback)이
섞여 있습니다. 3DGS 두 편은 깨끗합니다.

## 4. 이 작업에서 재사용 가능한 것

특정 결과와 무관하게 남는 자산입니다.

- **3-arm 통제 비교 하네스** — `scripts/compare_runs.py`. 분모 고정 지표와
  "코퍼스 다르면 비교 금지" 경고가 표에 내장돼 있습니다.
- **$0 배선 검사** — 편당 $2 를 쓰기 전에 조용히 틀리는 4곳을 숫자로 확인합니다.
- **후처리 자동화** — 생성 종료를 기다렸다 무결성·PDF·비교까지. SSH 가 끊겨도 돕니다.
- **PDF 변환기** — 유니코드·스냅샷 폴백 문제를 고치고 xelatex 자동 폴백을 넣었습니다.

## 5. 발표에서 솔직하게 말할 것

> "검색을 더 좋게 만들었지만 서베이는 더 좋아지지 않았습니다. 그런데 **어디서 끊기는지**는
> 알아냈고, 그 과정에서 **지금 벤치마크로 무엇을 잴 수 있고 무엇을 못 재는지**가
> 분명해졌습니다."

음성 결과를 숨기지 않는 편이 낫습니다. 이 작업에서 방어 가능한 것은 결과의 방향이 아니라
**측정 설계**입니다 — 분모가 바뀌는 지표를 발견해 고정 분모 지표를 붙였고, 그 둘이
정반대 순위를 낸다는 것까지 보였습니다.
