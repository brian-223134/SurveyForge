# temperature 검증 프로브 (2026-09-08)

**질문.** 원 SurveyForge 코드는 모델과 무관하게 모든 LLM 호출에 `temperature=1` 을 고정한다(upstream `writer.py`·`outline_writer.py` 7곳).
KISTI 비교 실험은 4개 agent 공통으로 **0.6** 을 쓰기로 했다(`kisti_data/docs/asg/AGENT-HANDOFF.md` §4). 0.6 은 Meta 가 Llama 3.x Instruct 에
배포하는 `generation_config.json` 값(temperature 0.6, top_p 0.9; meta-llama 저장소는 gated 라 unsloth 미러의 동일 파일로 확인)이다.
이 선택이 SurveyForge 의 프롬프트에서도 타당한지, 특히 AutoSurvey 에서 보고된 temp 0 반복 루프가 여기서도 나는지 본다.

**방법.** `scripts/probe_temperature.py`. bench-2512 스냅샷에서 집필 단계와 같은 경로(풀 1,500 → 풀 안 top-100 → TRE 60)로 논문
63편을 뽑아 실제 `SUBSECTION_WRITING_PROMPT`(17,227 토큰, WORD NUM 500)를 만들고, temperature 0 / 0.6 / 1.0 에서 4회씩
같은 프롬프트를 보냈다. 모델 `meta-llama/llama-3.3-70b-instruct` @ `akashml/fp8`, max_tokens 8192, 잘림 재요청 **꺼짐**(잘림을 그대로 관찰).
topic: Visual Adversarial Attacks and Defenses in the Physical World. 비용 약 $0.1.

## 읽기

- **세 temperature 모두 잘림 0, 반복 문장 0.** AutoSurvey 에서 관찰된 temp 0 반복 루프(호출 하나가 128K 토큰)는 SurveyForge 의
  서브섹션 프롬프트 12회에서는 재현되지 않았다. 루프는 프롬프트·출력 길이에 따라 다르게 나타나는 것으로 보인다 — 8,192 가드와
  재요청은 보험으로 유지한다.
- 길이(640~674 단어)·인용 수(15~17)·소요(32~34s)가 temperature 에 둔감하다. 지시값 500 단어에 대해 실제 640~670 단어로,
  AutoSurvey 에서 본 "지시 700 → 1,056" 과 같은 방향의 초과다.
- 따라서 SurveyForge 쪽에서는 **0.6 을 써도 잃는 것이 없고**, 1.0 을 써야 할 SurveyForge 고유의 이유도 없다. 결정은 4 agent 공통
  조건(입력 쪽 통제 변수) 차원에서 하면 된다: 지금은 0.6.
- top_p 는 보내지 않는다(provider 기본값). Meta 권장 프로파일을 온전히 쓰려면 top_p 0.9 도 보내야 하며, 이것도 4 agent 공통 결정 사항.
